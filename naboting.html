Om projektet

Naboting er en webapplikation, der gør det muligt for beboere i samme boligfællesskab at låne ting af hinanden. Systemet håndterer brugere, genstande, billeder, tilbehør og låneanmodninger.

Projektet blev udviklet som eksamensopgave med fokus på databasedesign, backend-logik og brugeroplevelsen i frontend.

Teknologi

Database

MySQL, normalisering til 3NF, ER-diagrammer og stored procedures

Backend

Node.js, Express.js, REST API og CRUD-operationer

Frontend

Vue.js, JavaScript, HTML5, CSS3 og responsivt design

Værktøjer

Git, MySQL Workbench, Postman og ER-diagramværktøjer

Kernefunktioner

  • BrugeradministrationRegistrering, login og brugerprofil med lokation
  • GenstandeOpret, redigér og slet genstande med kategori, tilstand og antal
  • BillederUpload af billeder med et system for primært billede
  • TilbehørTilknyt tilbehør til genstande, f.eks. kabler til elektronik
  • LåneanmodningerBeboere kan anmode om lån med start- og slutdato
  • LånestatusPending, approved, rejected og returned
  • KommunikationBesked mellem ejer og låner i låneformularen

Udviklingsprocessen

  1. Databasedesign

    Jeg startede med at definere entiteterne (brugere, genstande, billeder, tilbehør og lån) og deres relationer. Derefter normaliserede jeg til 3. normalform for at undgå redundans og sikre dataintegritet.

    • 1NF: Atomare værdier, så billeder og tilbehør ligger i separate tabeller
    • 2NF: Fuld afhængighed af primærnøglen
    • 3NF: Ingen afhængighed mellem ikke-nøglefelter

  2. Backend

    REST API bygget med Express.js og mysql2.

    • CRUD: POST-, GET-, PUT- og DELETE-endpoints
    • Stored procedures: CreateLoan med validering
    • Transaktioner: Sikrer konsistente data ved komplekse operationer
    • Fejlhåndtering: Fejl fra databasen og validering håndteres

  3. Frontend

    Bygget med Vue.js for en interaktiv brugeroplevelse.

    • Komponenter til genstandsliste, brugerprofil og låneformularer
    • Formularvalidering med feedback i realtid
    • Integration med backendens API
    • Responsivt design til mobil og desktop

Udfordringer og løsninger

Trigger-begrænsning i MySQL 5.7

Problem

En trigger skulle sikre, at kun ét billede ad gangen er "primært". MySQL tillader dog ikke, at en trigger ændrer data i den tabel, den selv er knyttet til.

Løsning

Logikken blev flyttet til backend med transaktioner. Først sættes alle eksisterende billeder til is_primary = 0, og derefter indsættes det nye med is_primary = 1.

Validering i databasen

Problem

Det skulle sikres, at en genstand ikke kan lånes, hvis den ikke er tilgængelig.

Løsning

Validering i den stored procedure CreateLoan, som tjekker status, før lånet oprettes.

Billedhåndtering

Problem

Skulle billeder gemmes som filer i databasen eller som URL'er?

Løsning

Billeder gemmes som URL'er og stier, så databasen er lettere og mere skalerbar.
